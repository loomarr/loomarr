TV auto-tune setting · design review (#1659 N4, #1817)

Mock for maintainer review before the picker is built (the stored duration is already wired: createTvAutoTuneSetting loads it in web/apps/tv/src/app.tsx, but nothing calls save). The Surf rail, channel cards, monogram idents, footer, hint chip, the DeviceDisconnectAction and its ModalOverlay are reproduced from the built source at density tv; the only new thing is the Channel-number wait row and its choice overlay. Drive it like a remote: ▲▼◀▶ arrow keys move focus, Enter = OK, Escape/Backspace = BACK, and on Watching 0–9 type a channel number. All channels, programmes, versions and the server address are invented; nothing calls a server.

Press an arrow key to start.

Copied pattern: OK opens a choice. The row is the design-system Action (density tv, tone secondary), the same primitive as “Disconnect device” beside it. OK opens a ModalOverlay exactly as DeviceDisconnectAction does (web/packages/ui/src/device-disconnect/device-disconnect.tsx, web/packages/ui/src/overlay/overlay.tsx): a scrim, the TV panel (max 880, padding 32), a title, a description, then a row of Actions walked by ◀▶ with the preferred-focus one focused first. BACK dismisses it (onRequestClose → onDismiss). Here the actions are the duration choices, the preferred focus is the current value, and the current value is drawn with Action’s existing selected state ($surfaceFocus fill, amber hairline). OK on a choice saves it and closes; focus returns to the row.

Chosen here, not sourced from code (please check each):

  • The row’s copy: one Action label Channel-number wait · 1.2 s. Action takes a single string, so label and value are joined with the “ · ” the rail footer already uses. At 24 px it may wrap in the 310 px the rail leaves inside the button; not measured on device.
  • Placement: the row sits directly above “Disconnect device”, so the destructive action stays last.
  • The overlay description copy (“After you type a channel number…”). ModalOverlay needs a title; the description is optional and could be dropped.
  • Choice labels drop a trailing “.0” (“2 s”, not “2.0 s”), while the countdown readout keeps one decimal (“auto-tunes in 2.0 s”) because that is how NumberEntry formats it.
  • OK on a choice saves at once and closes (no separate confirm). BACK leaves the value unchanged.
  • The picture behind the rail is a plain gradient placeholder; the fixtures (channel names, numbers, “18m left”, versions 0.2.0/0.2.1 from the map’s 5c copy, server http://192.0.2.10:8080) are invented.
  • Group header renders “FAVOURITES” (the code’s British label upper-cased), not “FAVORITES” as the map mock reads.

Open questions for the maintainer:

  1. The step list is not decided. Proposed: 1.2 s (default), 2 s, 3 s, 5 s, 10 s, all inside clampNumberEntryMs’s 1.2–10 s. Five fits one row of the 880 px panel. Keep, add more steps (e.g. 1.5 s, 7 s), or fewer?
  2. One string or a label/value row? A row with the label left and the value right would need a new layout (Action centres one string). Is the joined string acceptable?
  3. Reach. The row is at the end of the scroll, after every channel in “All channels”. With 54 channels that is ~60 ▼ presses (see state 1/3, where the rail is scrolled to the end). Is the foot of Surf the right home, or should it also be reachable sooner?
  4. Two ambers. Reproduced faithfully: the last-focused channel card keeps its amber “selected” border while focus is on the row or on Disconnect (selection only follows channel focus). That breaks “focus is the only amber”. Existing behaviour, not introduced here; flagging it because this row makes it more visible.
  5. Build note. OverlayAction has no selected field today, so marking the current value needs selected?: boolean passed through to Action in OverlayActions.
  6. Canvas. surf-rail.tsx’s comment says the TV rail assumes a 1280 px canvas; guide-tv.tsx uses 960. This mock draws 960×540 as asked.
