> **Release candidate.** This is the first candidate for beta.9, published so a household install can
> run it live. It is a prerelease: `latest` stays on beta.8, and the final `v0.2.0-beta.9` tag follows
> once this candidate has been verified on a real install.
>
> **Channels feel programmed, not played in order:**
> - **Shuffle works per channel (#1676, #1939).** Two channels with the same shows no longer air the
>   same sequence, and a shuffled channel reshuffles on every scheduling pass, so an episode doesn't
>   come back soon after it aired.
> - **Holiday episodes inside a series (#1930, #1934).** In season, a channel features a series' own
>   holiday episodes, such as Halloween specials in October. Each channel has a Holiday strength
>   setting and an option to favour evenings.
> - **Holiday membership is judged, not keyword-matched (#1931).** A title counts as a holiday title
>   only when the holiday is what it is about, or when it first aired in that holiday's window. A
>   title like *Ghost World* no longer joins a Halloween channel.
> - **Play order explains itself (#1933).** The Play order setting says what each choice means for
>   that channel.
>
> **Commercials (#1932, #1937):** breaks default to about two minutes and fill their time instead of
> dropping to the card. The same commercial repeats less often on a channel, with spacing you can set
> per channel. Region labels are accurate, so US-only filler is US-only.
>
> **On-screen logo (#1944):** six new watermark styles, colour, position and holiday versions,
> configured from the channel's On-screen logo section.
>
> **Also in this candidate:**
> - **Design system across the web app (#1817, #970).** It covers Programming defaults and overrides,
>   the Filler hierarchy, phone-width navigation, Home for quiet households, Help, sign-in and
>   pairing, and building a channel by hand when AI is off.
> - **Requests show the approval consequence (#1904, #1885).** Approving a group shows what it will
>   do, with exact sizes from the library.
> - **Phone and TV clients (#1816, #1500).** The phone app adds pairing, server discovery and
>   Requests. Apple TV fixes cover Menu going back and start-failure reasons. Paired apps report
>   crashes to their own server (#1912).
> - **Channel editors (#1895, #1899).** Every editor saves through one per-channel writer, so no
>   edit is lost.
>
> **Migration 133 is forward-only.** It adds client crash reports. Take a restorable backup of
> Loomarr's data directory before upgrading. Going back to beta.8 requires restoring that backup.
>
> **Known limitations:**
> - Each encoder checks whether it can draw a coloured logo. An encoder that fails the check airs
>   the coloured looks in white. Coloured airing has not yet been verified live on the Intel Arc
>   reference install.
> - On an install with mixed encoders, the logo preview can show colour for a channel that airs
>   white. The preview also shares a render lock with tuning and keeps an unbounded cache (#1949).
